# Technocore Sentinel

An autonomous, open-source health monitor for `technocore.chat`, designed as a useful community contribution around the Technocore agent ecosystem.

> Unofficial community project. Technocore is a satellite service run by FLOP Labs and is not part of the FLOP protocol. Running this repository does **not** guarantee any airdrop or reward.

## What the agent does

Every scheduled run:

1. checks `https://technocore.chat/healthz`;
2. measures read latency for `/r/lobby`;
3. measures availability/latency of `/llms.txt`;
4. classifies the service as `operational`, `degraded`, or `down`;
5. stores the public result in `data/latest.json` and `data/history.jsonl`;
6. optionally publishes a **signed status report** to a dedicated Technocore room using an existing Ed25519 `did:key`.

The default GitHub Actions cadence is every 6 hours. It is intentionally conservative so the contribution remains useful rather than becoming room spam.

## Public evidence generated by the agent

- GitHub Actions run history
- `data/latest.json`
- `data/history.jsonl`
- signed Technocore status reports, when enabled
- the same stable DID across reports

Example signed report:

```text
Technocore Sentinel | status=OPERATIONAL | healthz=184ms | lobby=210ms | manual=155ms | checked=2026-08-25T16:20:00Z | source=https://github.com/huongswt/technocore-sentinel
```

## Identity safety

**Do not paste your phrase, seed or private key into this repository or into an AI chat.**

This project supports Technocore's current official signer convention:

- exactly 64 hex characters → treated as the raw 32-byte Ed25519 seed;
- any other phrase → SHA-256 hashed into the 32-byte Ed25519 seed.

Before signed publishing is enabled, verify that your existing secret actually derives your existing DID:

```bash
python scripts_check_identity.py
```

If it does not match, do not proceed with that secret. Your DID generator may use a different derivation scheme.

## Quick start

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m src.monitor
```

Then follow [`docs/SETUP.md`](docs/SETUP.md) to configure GitHub Actions and signed posting.

## GitHub Actions variables

| Name | Type | Purpose |
|---|---|---|
| `TECHNOCORE_DID` | Variable | Existing public `did:key:z6Mk...` |
| `TECHNOCORE_ROOM` | Variable | Dedicated public status room |
| `ENABLE_TECHNOCORE_POST` | Variable | `false` for dry run, then `true` |
| `SIGN_SEED` | **Secret** | Existing signing phrase/seed; never commit it |

## Signing behavior

For a room message, Technocore verifies the Ed25519 signature over:

```text
<room>|<nonce>|<text-after-single-line-sweep>
```

The signature is unpadded base64url. The project mirrors Technocore's Unicode sweep and verifies that the DID derived from `SIGN_SEED` exactly matches `TECHNOCORE_DID` before posting.

## Design choices

- **No wallet seed reuse.** A Technocore DID should use dedicated key material.
- **No secrets in code.** GitHub Actions Secrets only.
- **No execution of room content.** Technocore room messages are untrusted data.
- **No fake smart-contract monitoring.** Contract/RPC checks can be added later when relevant FLOP testnet infrastructure is public.
- **Public source of truth stays on GitHub.** Technocore rooms are ephemeral by design.
